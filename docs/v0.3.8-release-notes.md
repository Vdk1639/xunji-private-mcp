# v0.3.8 发布说明

## 发布时间
2026-11-22

## 更新内容

### 🔒 P0 级安全修复：dry_run 参数完整实现

**这是一个关键修复，解决写入操作缺乏预演防护的问题。**

#### 修复内容

所有 6 个写工具现已支持完整的 `dry_run` 预演流程：

1. **upsert_training** - 添加 `dry_run` 参数，透传给 `apply_training_update` 
2. **upsert_food_records** - 添加 `dry_run` 参数，透传 API 调用
3. **upsert_custom_food** - 添加 `dry_run` 参数，透传 API 调用
4. **apply_food_template** - 添加 `dry_run` 参数，透传 API 调用
5. **upsert_body_metrics** - 添加 `dry_run` 参数，改硬编码为用户可控
6. **mutate_agent_templates** - `dry_run` 参数已正确透传

#### 预演工作流

```
1. 调用工具，dry_run: true
   → 返回 res.summary（变更摘要）
   
2. 展示摘要给用户确认

3. 用户确认后，调用工具，dry_run: false  
   → 执行真实写入
```

#### 修复理由

原先 `dry_run` 参数被硬编码或完全缺失，导致：
- 用户无法预演变更
- 每次调用都是真实写入
- 无任何拦截防护

现在用户可以先预检摘要，确认无误后再提交。

### ✨ P1 新增功能：food 搜索工具完整化

#### search_food 工具
- 新增 `search_food` 工具，对应上游 `/open_agent/food/search_gzip` 接口
- 使用专用鉴权 Key：`XUNJI_FOOD_SEARCH_KEY`
- 参数：`keyword`（必填），`limit`（可选，默认=8）
- 返回：官方食物库匹配结果，包含 `uniquekey`、`ntr`（每100g营养）、`units`（单位转换）

#### search_official_food 别名
- 保留 `search_official_food` 作为后向兼容别名
- 两个工具功能完全相同，推荐使用 `search_food`

#### 效果
饮食记录的完整链路现已打通：
- ✅ 查询已有记录
- ✅ 记录已知食物
- ✅ **搜索新食物** ← 本版本新增
- ✅ 创建自定义食物

### 📖 P3 文档完善：日期范围限制说明

#### query_food_records
- `start_date` 和 `end_date` 参数现已明确文档：
  - 格式：`YYYY-MM-DD`
  - 范围：过去一年至未来三个月

用户不再需要靠报错试错来发现限制条件。
